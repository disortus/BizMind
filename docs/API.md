## 🔐 Общие сведения и аутентификация

* **Базовый URL**: `http://localhost:8000/api` (в продакшене проксируется через Nginx на `/api`)
* **Формат данных**: `application/json` (для импорта файлов: `multipart/form-data`)
* **Авторизация**: Заголовок `Authorization: Bearer <token>` или сессионная cookie. В демо-режиме запросы без токена используют контекст активной организации по умолчанию (`organization_id = 1` или `2`).
* **Интерактивная документация**:
  * Swagger UI: `http://localhost:8000/docs`
  * ReDoc: `http://localhost:8000/redoc`

## 👤 Аутентификация и пользователи (`/api/auth`)

### `POST /api/auth/login`
Авторизация пользователя по email и паролю.
* **Тело запроса**:
  ```json
  {
    "email": "owner@aroma.kz",
    "password": "demo_password"
  }
  ```
* **Ответ `200 OK`**:
  ```json
  {
    "access_token": "eyJhbGciOi...",
    "token_type": "bearer",
    "user": {
      "id": 1,
      "email": "owner@aroma.kz",
      "name": "Азамат Сериков",
      "role": "owner",
      "organization_id": 1
    }
  }
  ```

### `GET /api/auth/me`
Получение данных текущего аутентифицированного пользователя.

### `POST /api/auth/logout`
Завершение сеанса.

## 📊 Дашборд и сводные показатели (`/api/dashboard`)

### `GET /api/dashboard/stats`
Возвращает ключевые операционные показатели (KPI) бизнеса:
* Выручка за текущий месяц
* Операционные расходы
* Чистая прибыль
* Сохраненная экономия (Realized Savings)
* Количество критических алертов
* Количество позиций с запасом ниже минимального

### `GET /api/dashboard/summary`
Возвращает расширенную аналитическую сводку для графиков главной страницы: динамика расходов за 6 месяцев, топ поставщиков по объему оплат, распределение затрат по категориям.

## 🤝 Поставщики, офферы и каталог (`/api/suppliers`)

### `GET /api/suppliers`
Список контрагентов организации + глобальные поставщики маркетплейса.
* **Query-параметры**:
  * `category` *(строка)*: Фильтр по категории поставляемого сырья
  * `is_global` *(boolean)*: Только глобальные или только локальные

### `POST /api/suppliers`
Создание нового локального поставщика.

### `GET /api/suppliers/{id}`
Детальная карточка поставщика с условиями доставки, минимальным заказом и контактными данными.

### `GET /api/suppliers/{id}/catalog`
⭐️ **Каталог товаров выбранного поставщика** с зафиксированными ценами, минимальным объемом (MOQ), единицами измерения и условиями кратности упаковки.
* **Ответ `200 OK`**:
  ```json
  {
    "supplier": {
      "id": 1,
      "name": "ТОО \"Coffee Trade KZ\"",
      "minimum_order_amount": 10000.0,
      "delivery_cost": 1500.0
    },
    "items": [
      {
        "product_id": 1,
        "product_name": "Кофе в зернах Espresso Blend",
        "category": "Кофе",
        "offered_price": 5400.0,
        "unit": "кг",
        "minimum_order_quantity": 5.0,
        "package_quantity": 1.0,
        "current_stock": 14.5
      }
    ]
  }
  ```

### `GET /api/suppliers/compare`
Матрица сравнения предложений поставщиков по номенклатуре:
* Поиск альтернативных поставщиков
* Расчет дельты цен и потенциальной экономии
* Учет стоимости доставки и минимального заказа

### `GET /api/suppliers/price-history`
История изменения цен поставщиков с процентами колебаний и датами.

## 🛒 Заказы на поставку (`/api/orders`)

### `GET /api/orders`
Список сформированных заказов.
* **Query-параметры**:
  * `status`: `'draft'`, `'confirmed'`, `'received'`, `'cancelled'`
  * `supplier_id`: фильтр по поставщику
  * `date_from`, `date_to`: временной диапазон

### `POST /api/orders`
Создание нового заказа на поставку.
* **Валидация**:
  1. Позиции выбираются строго из каталога поставщика.
  2. Цены фиксируются из офферов (`catalog price locking`).
  3. Проверяется MOQ по позициям (`quantity >= item.minimum_order_quantity`).
  4. Проверяется минимальная сумма заказа поставщика (`subtotal >= supplier.minimum_order_amount`).
* **Тело запроса**:
  ```json
  {
    "supplier_id": 1,
    "notes": "Поставка на утреннюю смену",
    "items": [
      {
        "product_id": 1,
        "quantity": 10.0
      }
    ]
  }
  ```

### `GET /api/orders/{id}`
Детализация заказа со спецификацией позиций, суммами, историей статусов.

### `PUT /api/orders/{id}` и `PATCH /api/orders/{id}`
⭐️ **Редактирование черновика заказа** (доступно только в статусе `draft`). Позволяет изменить примечания, скорректировать количества или обновить список заказываемых позиций с пересчетом итогов и повторной проверкой MOQ.

### `POST /api/orders/{id}/confirm`
Перевод заказа в статус `confirmed` (подтвержден поставщиком, ожидает доставки).

### `POST /api/orders/{id}/receive`
⭐️ **Оприходование поставки на склад**:
* Переводит заказ в статус `received`.
* Формирует приходные складские движения `InventoryMovement(movement_type='receipt')`.
* Увеличивает `Product.current_stock`.
* Создает расходную финансовую проводку `FinancialTransaction(expense)`.
* Фиксирует запись в аудите `ActivityLog`.

### `POST /api/orders/{id}/cancel`
Отмена заказа (в статусе `draft` или `confirmed`).

## 📦 Склад и запасы (`/api/inventory`)

### `GET /api/inventory`
Список складских остатков номенклатуры:
* Текущий остаток (`current_stock`)
* Страховой запас (`minimum_stock`)
* Статус (`норма`, `критический остаток`, `исчерпано`)
* Оценка стоимости остатка

### `GET /api/inventory/movements`
Журнал всех складских движений (приходы, списания, инвентаризации).

### `POST /api/inventory/write-off`
Списание сырья (порча, брак, расход на дегустацию):
* Снижает `Product.current_stock`.
* Создает запись `InventoryMovement(movement_type='write_off')`.

### `POST /api/inventory/adjust`
Корректировка остатка по результатам ревизии (инвентаризации).

### `GET /api/inventory/export`
Выгрузка актуальной складской ведомости в формате Excel (`.xlsx`) или CSV.

## 🏷️ Товары и ингредиенты (`/api/products`)

* `GET /api/products`: Справочник номенклатуры организации.
* `POST /api/products`: Создание новой номенклатурной единицы.
* `GET /api/products/{id}`: Карточка товара с историей цен и активными предложениями.
* `PUT /api/products/{id}`: Обновление параметров товара (категория, единицы, минимальный запас).
* `DELETE /api/products/{id}`: Деактивация товара.

---

## 💰 Финансы и ДДС (`/api/finances`)

* `GET /api/finances`: Реестр финансовых транзакций с фильтрацией по типу (`expense`/`income`), категории и датам.
* `POST /api/finances`: Ручное внесение финансовой проводки.
* `GET /api/finances/stats`: Аналитика ДДС: доходы, расходы, операционный денежный поток.
* `GET /api/finances/export`: Экспорт проводок в Excel/CSV.

---

## 🚚 Аналитика закупок (`/api/purchases`)

* `GET /api/purchases`: Исторический реестр фактических поставок.
* `GET /api/purchases/stats`: Структура закупок по поставщикам и категориям сырья.

---

## 🔮 Прогнозирование исчерпания (`/api/forecast`)

### `GET /api/forecast`
Интеллектуальный расчет темпов расходования запасов:
* Среднесуточный расход сырья на основе аналитики списаний и продаж
* Оценка количества дней до полного исчерпания каждого ингредиента
* Рекомендованные сроки и объемы новых закупок

---

## 📑 Конструктор отчетов (`/api/reports`)

### `GET /api/reports/templates`
Список шаблонов (системные пресеты + пользовательские шаблоны).

### `POST /api/reports/templates`
Сохранение нового шаблона с JSON-конфигурацией.

### `PUT /api/reports/templates/{id}`
Обновление конфигурации шаблона.

### `DELETE /api/reports/templates/{id}`
Удаление/архивация шаблона.

### `POST /api/reports/generate`
Генерация данных отчета по переданной конфигурации или ID шаблона:
* Расчет KPI сводки
* Таблицы группировок по категориям/поставщикам
* Серии для графиков динамики

### `POST /api/reports/export`
Экспорт сформированного отчета в Excel (`.xlsx`) или CSV.

---

## 📥 Импорт внешних данных (`/api/imports`)

### `POST /api/imports/upload`
Загрузка файлов Excel (`.xlsx`, `.xls`) или CSV.
* **Форм-дата**: `file`, `import_type` (`finances`, `purchases`, `inventory`, `supplier_prices`)
* **Ответ `200 OK`**:
  ```json
  {
    "batch_id": 12,
    "status": "success",
    "rows_total": 50,
    "rows_imported": 48,
    "rows_skipped": 2,
    "warnings": ["Строка 14: Пропущена, некорректная дата"]
  }
  ```

### `GET /api/imports/batches`
История загрузок файлов с результатами валидации.

---

## 🔔 Уведомления и алерты (`/api/notifications`)

* `GET /api/notifications`: Список активных предупреждений (скачки цен, нехватка остатков, выгодные альтернативы).
* `POST /api/notifications/{id}/read`: Отметка о прочтении конкретного уведомления.
* `POST /api/notifications/read-all`: Отметка всех уведомлений как прочитанных.

## ⚙️ Настройки и сотрудники (`/api/settings`)

### `GET /api/settings/organization`
Параметры текущей организации (название, валюта, порог алертов, адрес, телефон).

### `PUT /api/settings/organization`
Обновление настроек бизнеса.

### `GET /api/settings/employees`
Список учетных записей сотрудников организации с их ролями.

### `POST /api/settings/employees`
⭐️ **Добавление нового сотрудника**:
* Поддерживает передачу явного пароля или генерацию безопасного пароля.
* В UI реализован переключатель видимости пароля и кнопка «Сгенерировать пароль».
* Роли: `owner`, `manager`, `employee`.

### `PUT /api/settings/employees/{id}`
Изменение роли или активности сотрудника.

### `DELETE /api/settings/employees/{id}`
Удаление/деактивация доступа сотрудника.

### `GET /api/settings/audit-logs`
Журнал аудита действий пользователей (Activity Log).

## 🧪 Управление демонстрацией (`/api/demo`)

* `GET /api/demo/scenarios`: Список демонстрационных сценариев (`Сценарий А: Кофейня Арома`, `Сценарий Б: Daily Cup`).
* `POST /api/demo/switch`: Переключение контекста на выбранный сценарий.
* `POST /api/demo/reset`: Сброс базы данных к начальному детерминированному эталону.
* `GET /api/demo/status`: Проверка текущего режима и версии стенда.
