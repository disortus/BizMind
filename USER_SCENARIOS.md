# Пошаговые пользовательские сценарии BizMind (User Scenarios)

> **Назначение документа:** Руководство для преподавателя, экзаменационной комиссии и тестировщика. Содержит точные пошаговые инструкции проверки всех реализованных возможностей учебного MVP BizMind на ветке `feature/educational-mvp`.  
> **Окружение:** Локальный запуск (Docker Compose или `uv run` + `npm run dev`).  
> **Тестовая база:** Автоматически инициализируемые демо-организации «Cafe Aroma» (Кейс A — первичное внедрение) и «Daily Cup» (Кейс B — регулярное использование).

### Сценарий 1: Первый запуск и выбор демонстрационного кейса
* **Начальное состояние:** Приложение запущено, в браузере открыта страница `http://localhost:5173` (или `http://localhost`). Локальное хранилище браузера чистое.
* **Последовательность действий:**
  1. Откройте главную страницу. Отображается экран входа с карточками демонстрационных пространств.
  2. Ознакомьтесь с карточками:
     - **Кейс А: Cafe Aroma** — режим первичного внедрения (выявление скачка цен на зерно +15%, дефицит молока, неразобранные счета).
     - **Кейс Б: Daily Cup** — режим стабильного использования (сеть из 2 точек, регулярные поставки, сформированные прайс-листы).
  3. Нажмите кнопку **«Войти в пространство Cafe Aroma»**.
* **Ожидаемый результат:**
  - Приложение сохраняет активную организацию `id=1` в `localStorage` (`bizmind_org_id`).
  - Выполняется переход на **Сводный дашборд** Cafe Aroma.
  - В шапке отображается бейдж: `Cafe Aroma • Первоначальное внедрение`.

### Сценарий 2: Аутентификация и ролевой вход
* **Начальное состояние:** Вход выполнен под владельцем кофейни.
* **Последовательность действий:**
  1. В боковом меню перейдите в раздел **«Настройки»** -> вкладка **«Команда и роли»**.
  2. Проверьте список пользователей организации. Присутствуют учетные записи:
     - `owner@cafearoma.kz` (Роль: *Владелец / Owner*).
     - `manager@cafearoma.kz` (Роль: *Управляющий / Manager*).
     - `barista@cafearoma.kz` (Роль: *Сотрудник / Employee*).
  3. Нажмите кнопку **«Добавить сотрудника»** (доступна только владельцу):
     - Имя: `Алексей Смирнов`
     - Email: `alex@cafearoma.kz`
     - Роль: `Manager (Управляющий)`
     - Пароль: `Manager2026!`
  4. Нажмите **«Зарегистрировать»**.
* **Ожидаемый результат:**
  - Новый пользователь сохранен в базе данных с криптографическим хешем пароля (PBKDF2-HMAC-SHA256).
  - В таблице сотрудников появилась новая строка со статусом «Активен».
  - В системный журнал аудита записано событие создания пользователя.

### Сценарий 3: Просмотр и редактирование реквизитов организации
* **Начальное состояние:** Открыт раздел **«Настройки»** -> вкладка **«Профиль предприятия»**.
* **Последовательность действий:**
  1. Измените поле «Контактный телефон» на `+7 (727) 355-12-88`.
  2. Измените «Порог алерта о росте цен» с `5%` на `7%`.
  3. Укажите адрес: `г. Алматы, ул. Абая 44, кофейня 1`.
  4. Нажмите кнопку **«Сохранить изменения»**.
* **Ожидаемый результат:**
  - Появится зеленое уведомление: `«Настройки успешно сохранены!»`.
  - Изменения персистентно записаны в SQLite в таблицу `organizations`.
  - При перезагрузке страницы введенные телефон и адрес сохраняются.

### Сценарий 4: Создание новой товарной позиции в каталоге
* **Начальное состояние:** В боковом меню выбран раздел **«Склад»**.
* **Последовательность действий:**
  1. Нажмите кнопку **«Новый товар»** в правом верхнем углу.
  2. Заполните форму:
     - Наименование: `Сироп Карамель 1л`
     - Категория: `Расходные материалы`
     - Единица измерения: `шт`
     - Артикул (SKU): `SYR-CRM-01`
     - Начальный остаток: `10`
     - Минимальный неснижаемый остаток: `4`
     - Описание: `Сироп для рафа и латте, стекло 1000 мл`
  3. Нажмите кнопку **«Создать товар»**.
* **Ожидаемый результат:**
  - Товар добавлен в таблицу остатков склада.
  - Текущий остаток отображается: `10 шт`, статус: `В норме`.
  - Во вкладке **«Журнал движений»** автоматически зафиксирована запись типа `Начальный остаток` (+10 шт).

### Сценарий 5: Добавление поставщика и регистрация цен
* **Начальное состояние:** В боковом меню выбран раздел **«Сравнение цен»**.
* **Последовательность действий:**
  1. Обратите внимание на список поставщиков (Tasty Coffee, Coffee Workshop, Almaty Bean Co., Dairy Milk, Eco Cup).
  2. Выберите товар `Сироп Карамель 1л` или воспользуйтесь API для добавления предложения.
  3. Для существующего кофе `Espresso Blend` откройте карточку предложений:
     - Текущий поставщик: *Tasty Coffee* (цена `8 200 ₸/кг`).
     - Альтернативный поставщик: *Coffee Workshop* (цена `7 100 ₸/кг`, мин. партия 10 кг, доставка 3 000 ₸).
* **Ожидаемый результат:**
  - Система сопоставляет цены за общую единицу (1 кг).
  - Отображается разница за единицу (`-1 100 ₸/кг`, выгода 13.4%).
  - Если дата предложения старше 30 дней, выводится предупреждающий бейдж `Прайс-лист устарел`.

### Сценарий 6: Скачивание шаблона и импорт прайс-листа
* **Начальное состояние:** Открыт раздел **«Импорт и данные»**.
* **Последовательность действий:**
  1. В правом блоке найдите карточку **«Шаблоны таблиц для заполнения»**.
  2. Нажмите на бейдж **«.XLSX»** напротив строки «Прайс-листы поставщиков».
  3. Браузер скачивает сгенерированный сервером файл-шаблон с корректными заголовками:
     `Поставщик, Товар, Категория, Цена, Единица, Мин. партия, Доставка`.
  4. В левой форме выберите «Тип данных»: `Прайс-листы поставщиков`.
  5. В блоке демо-файлов нажмите кнопку скачивания файла `cafe_aroma_alternative_offers.xlsx`.
  6. Перетащите скачанный файл в область загрузки.
  7. Отобразится блок «Предварительный просмотр структуры» с первыми строками таблицы.
  8. Нажмите зеленую кнопку **«Подтвердить и импортировать данные»**.
* **Ожидаемый результат:**
  - Выводится сообщение: `«Импорт успешно выполнен: обработано 5 строк, ошибок: 0»`.
  - В таблице «История пакетных импортов» появляется новая запись с отметкой `Успешно`.
  - Предложения появляются в модуле сравнения цен.

### Сценарий 7: Загрузка файла с ошибками и проверка протокола валидации
* **Начальное состояние:** Открыт раздел **«Импорт и данные»**.
* **Последовательность действий:**
  1. Выберите тип данных: `Финансовые операции`.
  2. В блоке демо-файлов скачайте файл с дефектами `corrupted_finances_sample.xlsx` (или создайте файл с отрицательной суммой, пропущенной датой или неизвестным типом операции).
  3. Загрузите файл и нажмите **«Подтвердить и импортировать»**.
* **Ожидаемый результат:**
  - Сервер выполняет валидацию каждой строки.
  - В блоке результатов отображается: `Статус: Ошибки валидации (Частично или Отклонено)`.
  - Подробный протокол ошибок указывает точные номера строк и причину:
    `• Строка 3: Некорректная сумма: отрицательное значение`
    `• Строка 5: Поле "Категория" обязательно для заполнения`.
  - Некорректные данные не разрушают целостность базы данных.

### Сценарий 8: Сравнение предложений поставщиков и расчет экономии
* **Начальное состояние:** Открыт экран **«Сравнение цен»**.
* **Последовательность действий:**
  1. Выберите в селекторе товар: `Кофе Espresso Blend`.
  2. Укажите объем закупки: `30` кг.
  3. Ознакомьтесь с блоком калькуляции:
     - Закупка у текущего поставщика (Tasty Coffee): $30 \times 8\,200 = 246\,000\text{ ₸}$.
     - Закупка у альтернативного поставщика (Coffee Workshop): $30 \times 7\,100 + 3\,000\text{ (доставка)} = 216\,000\text{ ₸}$.
     - Потенциальная разница: $+30\,000\text{ ₸}$ ($12.2\%$).
* **Ожидаемый результат:**
  - Система наглядно поясняет формулу расчета: учитывает цену за килограмм, минимальный объем (10 кг) и платную доставку (3 000 ₸).
  - Разница четко обозначена как *потенциальная выгода*, а не свершившийся факт.

### Сценарий 9: Создание и согласование заказа поставщику (Черновик -> Подтвержден)
* **Начальное состояние:** Открыт экран **«Заказы»** (`/orders`).
* **Последовательность действий:**
  1. Нажмите кнопку **«Сформировать заказ»**.
  2. В модальном окне выберите:
     - Поставщик: `Coffee Workshop`
     - Дата заказа: сегодняшнее число
     - Ожидаемая дата доставки: через 2 дня
     - Доставка: `3000` ₸
     - Примечание: `Тестовая поставка кофе для кофейни`
  3. В позициях спецификации укажите:
     - Товар: `Кофе Espresso Blend`
     - Количество: `20` кг
     - Цена за единицу: `7100` ₸
  4. Нажмите **«Создать черновик»**.
  5. В списке заказов появится новый заказ с номером `PO-202610...` и желтым статусом `Черновик`.
  6. На карточке заказа нажмите синюю кнопку **«Подтвердить»**.
* **Ожидаемый результат:**
  - Статус заказа меняется на `Подтвержден` (синий бейдж).
  - В счетчике карточек KPI показатель «Ожидают поставки» увеличивается на 1.
  - Заказ готов к приему водителем-экспедитором.

### Сценарий 10: Формирование печатного бланка накладной
* **Начальное состояние:** В разделе **«Заказы»** найден созданный подтвержденный заказ.
* **Последовательность действий:**
  1. Нажмите кнопку **«Бланк»** на карточке заказа.
  2. Открывается модальное окно с готовой текстовой формой накладной:
     - Номер заказа и дата оформления
     - Реквизиты покупателя (Cafe Aroma) и поставщика (Coffee Workshop)
     - Табличная часть со списком позиций, единицами, ценами и итогом
     - Поля для подписей «Отпустил» и «Принял».
  3. Нажмите кнопку **«Копировать»** (текст попадает в буфер обмена для отправки поставщику в WhatsApp/Telegram) или **«Печать»** (вызов системного диалога печати).
* **Ожидаемый результат:**
  - Бланк сформирован сервером динамически на основе реальных данных БД без необходимости внешнего почтового сервиса.

### Сценарий 11: Приемка поставки на склад (Складские движения + Финансы)
* **Начальное состояние:** Заказ находится в статусе `Подтвержден`. В разделе «Склад» текущий остаток кофе Espresso Blend равен, например, `12 кг`.
* **Последовательность действий:**
  1. На карточке заказа нажмите зеленую кнопку **«Принять на склад»**.
  2. В появившемся диалоге подтвердите приемку:
     `«Подтвердить приемку поставки? Товары будут оприходованы на склад, а сумма заказа отразится в расходах»`.
  3. Нажмите «ОК».
  4. Перейдите в раздел **«Склад»**.
  5. Перейдите в раздел **«Финансы»**.
* **Ожидаемый результат:**
  - Статус заказа меняется на `Поступил на склад` (зеленый бейдж). Повторно принять заказ невозможно (кнопка исчезает).
  - На складе: остаток `Кофе Espresso Blend` увеличился ровно на `+20 кг` (стал `32 кг`).
  - В журнале движений склада появилась запись типа `Поступление` со ссылкой на номер заказа.
  - В финансовых операциях появилась расходная транзакция на общую сумму заказа ($20 \times 7\,100 + 3\,000 = 145\,000\text{ ₸}$) с привязкой к заказу `purchase_order_id`, что исключает двойной учет при повторном анализе.

### Сценарий 12: Проведение инвентаризации и списания брака
* **Начальное состояние:** Открыт раздел **«Склад»**, вкладка «Текущие остатки».
* **Последовательность действий:**
  1. **Инвентаризация:**
     - Найдите товар `Молоко ультрапастеризованное 3.2%`.
     - Нажмите кнопку **«Инвентаризация»**.
     - В модальном окне введите фактический остаток: вместо 8 л укажите `15` л.
     - Причина: `Пересчет при закрытии смены`.
     - Нажмите **«Зафиксировать»**.
     - Остаток мгновенно стал `15 л`, в журнале появилась строка корректировки (+7 л).
  2. **Списание:**
     - Найдите товар `Стаканчики 250мл`.
     - Нажмите кнопку **«Списать»**.
     - Количество: `20` шт.
     - Причина: `Производственный брак / бой`.
     - Нажмите **«Списать со склада»**.
* **Ожидаемый результат:**
  - Остаток стаканчиков уменьшился на 20 шт.
  - Журнал движений фиксирует точную причину списания, дату и автора операции.

### Сценарий 13: Ввод ручной финансовой операции и защита от двойного учета
* **Начальное состояние:** Открыт раздел **«Финансы»**.
* **Последовательность действий:**
  1. Нажмите кнопку **«Добавить операцию»**.
  2. Заполните форму:
     - Тип: `Расход`
     - Категория: `Аренда помещения`
     - Сумма: `250000` ₸
     - Дата: сегодняшняя дата
     - Назначение платежа: `Оплата аренды за текущий месяц (кофейня 1)`
  3. Нажмите **«Сохранить операцию»**.
  4. Найдите строку в таблице. Сумма отображается со знаком минус (`−250 000 ₸`).
  5. Проверьте итоговые плашки: «Совокупные расходы» и «Чистый операционный результат» пересчитались мгновенно.
  6. При необходимости нажмите иконку корзины на строке для безопасного удаления операции.
* **Ожидаемый результат:**
  - Операция сохранена в БД с признаком ручного ввода `source: manual`.
  - Заказы, принятые через модуль закупок, имеют отметку `source: purchase_order`, поэтому финансовый модуль разделяет источники списаний.

### Сценарий 14: Просмотр сводного дашборда и динамики
* **Начальное состояние:** Внесены финансовые операции и принят заказ.
* **Последовательность действий:**
  1. Перейдите в раздел **«Дашборд»**.
  2. Переключайте фильтры периода: `7 дней`, `30 дней`, `90 дней`.
  3. Ознакомьтесь с виджетами:
     - «Совокупные расходы» и динамика в процентах относительно прошлого периода.
     - «Чистый результат» (Выручка минус подтвержденные расходы).
     - График «Динамика расходов и выручки» (Recharts).
     - Круговая диаграмма «Структура расходов по категориям».
     - Виджет «Ключевая возможность оптимизации» (сравнение с альтернативным поставщиком).
     - Виджет «Потребность в закупках» (позиции с низким остатком).
* **Ожидаемый результат:**
  - Ни одно число не является статичной строкой — все показатели агрегируются бэкендом из SQLite SQL-запросами на лету.

### Сценарий 15: Обработка уведомлений о ценах и дефиците
* **Начальное состояние:** В боковом меню возле пункта «Уведомления» отображается бейдж с количеством непрочитанных алертов.
* **Последовательность действий:**
  1. Нажмите на вкладку **«Уведомления»** (или колокольчик в верхней панели).
  2. Просмотрите сгенерированные системой карточки:
     - Рост цены у поставщика: `«Поставщик Tasty Coffee повысил цену на Кофе Espresso Blend на 15.0%»` (красный бейдж опасности).
     - Дефицит запаса: `«Критический остаток товара Молоко: осталось 8 л (минимум 15 л)»`.
     - Спецификация: `«Есть черновики заказов, ожидающие согласования»`.
  3. Нажмите кнопку **«Перейти к сравнению»** на уведомлении о росте цен — приложение автоматически переключает вас на экран Comparison с выбранным товаром.
  4. Вернитесь в Уведомления и нажмите **«Прочитано»** на карточке.
* **Ожидаемый результат:**
  - Счетчик непрочитанных уменьшается.
  - Уведомления генерируются правилами сервиса, а не дублируются при каждом обновлении страницы.

### Сценарий 16: Проверка изоляции данных (Переключение на Daily Cup)

### Сценарий 17: Экспорт аналитических отчетов в Excel и CSV
* **Начальное состояние:** Открыт раздел **«Финансы»** или **«Склад»**.
* **Последовательность действий:**
  1. В разделе **«Финансы»** нажмите кнопку **«Excel»** в верхней панели фильтров.
  2. Браузер скачивает файл `finances_export_YYYYMMDD.xlsx`. Откройте его в Excel/LibreOffice — файл содержит все отфильтрованные транзакции с датами, категориями и суммами.
  3. Нажмите кнопку **«CSV»** — скачивается файл `finances_export_YYYYMMDD.csv` в кодировке UTF-8 с разделителями-запятыми.
  4. Перейдите в раздел **«Склад»** и нажмите **«Excel»** — скачивается актуальная ведомость остатков склада `inventory_balance_YYYYMMDD.xlsx`.
* **Ожидаемый результат:**
  - Экспорт формируется на лету через `pandas` и `openpyxl` на бэкенде, файлы открываются без ошибок форматирования.

### Сценарий 18: Просмотр системного журнала аудита (Audit Trail)
* **Начальное состояние:** В системе выполнены создание товара, корректировка остатка, приемка заказа и сохранение настроек.
