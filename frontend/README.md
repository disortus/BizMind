# BizMind Frontend Application

> **Модуль:** Веб-клиент аналитической платформы BizMind  
> **Версия:** 1.0.0  
> **Стек:** React 19, TypeScript, Vite 8, Tailwind CSS, Recharts, Lucide Icons, Axios

---

## 1. Обзор приложения

Фронтенд BizMind — это одностраничное веб-приложение (SPA), разработанное для оперативной визуализации ключевых показателей кофейни/магазина:
- Управление закупками и выявление скрытой инфляции от поставщиков.
- Интерактивное сопоставление альтернативных коммерческих предложений.
- Контроль остатков на складе и предупреждение о дефиците позиций.
- Анализ структуры операционных расходов и финансового сальдо.
- Загрузка и аудит импорта файлов Excel/CSV.
- Мгновенное переключение между демонстрационными бизнес-кейсами.

## 3. Ключевые механизмы и состояние приложения

### 3.1. Экран выбора кейса (`LoginPage.tsx`)
При первом открытии приложения (когда в `localStorage` отсутствует сохранённая организация), открывается экран выбора сценария:
- **Кейс A: Кофейня «Cafe Aroma» (Организация 1)** — сценарий первичного внедрения и миграции с Excel. Демонстрирует скачок цен на зерновой кофе (+15%) и нехватку молока 3.2% (< 3 дней).
- **Кейс B: Кофейня «Daily Cup» (Организация 2)** — сценарий регулярной работы (5+ месяцев в системе). Демонстрирует рост цен на крафтовые стаканы 250 мл (+18.3%) и нехватку подстаканников.

### 3.2. Мультитенантность на клиенте (`api.ts`)
Клиент хранит выбранный идентификатор организации в `localStorage`:
- Ключ: `bizmind_org_id`.
- Axios Request Interceptor автоматически подставляет заголовок в каждый запрос к бэкенду:
  ```typescript
  config.headers['X-Organization-Id'] = orgId;
  ```
- Для выхода к экрану выбора кейсов реализован метод `api.logout()`, очищающий идентификатор тенанта.

### 3.3. Отказоустойчивость (`ErrorBoundary.tsx`)
Корневой компонент `<App />` обёрнут в класс `ErrorBoundary`, перехватывающий любые непредвиденные ошибки рендера React. При сбое пользователю выводится информативный интерфейс со стектрейсом ошибки и кнопками быстрого восстановления («Перезагрузить страницу», «Сбросить сессию и вернуться к выбору кейса»).

## 4. Разделы и функциональность страниц

### 4.1. Сводный дашборд (`DashboardPage.tsx`)
- **Карточки KPI:** Доходы, Расходы, Чистый баланс, Индекс экономии за выбранный период.
- **Инфляционный баннер:** Наглядная индикация подорожания ключевого ингредиента с расчётом переплаты и прямой кнопкой перехода к альтернативным поставщикам.
- **Интерактивный экспресс-калькулятор партии:** Позволяет ползунком менять объём заказа и на лету видеть чистую выгоду в тенге (₸).
- **График динамики расходов:** Интерактивная диаграмма на базе `Recharts` с разбивкой по статьям (сырье, аренда, упаковка).
- **Топ статей расходов:** Горизонтальные прогресс-бары с долями затрат.

### 4.2. Финансы (`FinancesPage.tsx`)
- Таблица операций с цветовой кодировкой доходов (зеленый) и расходов (красный/розовый).
- Фильтрация по типам операций и статьям расходов.
- Модальное окно ручного внесения операции с мгновенным пересчетом баланса.

### 4.3. Закупки и аудит цен (`PurchasesPage.tsx`)
- Детализация по каждой партии: товар, поставщик, дата, объем, цена за единицу.
- Бейджи динамики цен: маркеры $\ge +5\%$ подсвечиваются предупреждающим цветом.
- Кнопка вызова модального окна `ProductHistoryModal` с графиком изменения закупочной стоимости за весь исторический период.

### 4.4. Сравнение предложений (`ComparisonPage.tsx`)
- Матрица сопоставления коммерческих предложений от разных поставщиков по конкретному товару.
- Автоматический учёт минимального объёма заказа (MOQ) и стоимости доставки.
- Индикатор «Рекомендуемый выбор» для лучшего предложения.

### 4.5. Прогноз запасов (`ForecastPage.tsx`)
- Цветовая индикация дней до истощения:
  - 🔴 **Критический (< 3 дней):** риск стоп-листа в меню.
  - 🟡 **Внимание (3–7 дней):** требуется сформировать заказ.
  - 🟢 **В норме (> 7 дней):** достаточный складской запас.
- Расчёт рекомендуемого объёма пополнения с учётом неснижаемого остатка.

### 4.6. Импорт данных (`ImportSettingsPage.tsx`)
- Загрузка файлов `.xlsx` с автоопределением структуры колонок.
- Скачивание готовых эталонных демо-таблиц для каждого кейса.
- Кнопка аварийного сброса базы данных к исходному состоянию.

## 5. Адаптивность и мобильный интерфейс (Responsive UX & Mobile Layout)

Интерфейс BizMind оптимизирован для работы на экранах любых размеров: от мобильных устройств (320px–480px) и планшетов (768px–1024px) до широкоформатных мониторов (1280px+). При этом **исходный дизайн, сетка и функционал десктопной версии полностью сохранены** на экранах `lg+` (от 1024px).

### 5.1. Принципы адаптивной вёрстки
- **Сохранение десктопной эстетики:** Премиальная тёмная тема (`#0B0F17`, `#161F30`, `#243045`) с изумрудными (`emerald`) и бирюзовыми (`teal`) акцентами выглядит идентично на десктопе и органично перестраивается на компактных дисплеях.
- **Плавное масштабирование паддингов и сеток:** На всех страницах применены адаптивные контейнеры `p-4 sm:p-6 lg:p-8 space-y-4 sm:space-y-6 max-w-7xl mx-auto`.
- **Эргономика сенсорного ввода (Touch Ergonomics):** Интерактивные элементы (кнопки, табы, элементы списков) имеют минимальную высоту зоны клика 38–44px для комфортного нажатия пальцем.

### 5.2. Мобильная навигация (Off-canvas Drawer)
- **Боковая панель (`Sidebar.tsx`):**
  - На десктопе (`lg:flex`): Стационарный сайдбар фиксированной ширины (`w-64`).
  - На мобильных (`< lg`): Полнофункциональный выдвижной ящик (Drawer) шириной `w-72 max-w-[85vw]` с полупрозрачным фоном-блюром (`bg-slate-950/75 backdrop-blur-sm`) и кнопкой закрытия (`X`).
  - **Автоматическое закрытие:** Сайдбар автоматически сворачивается при переходе в любой раздел, смене организации или нажатии на затемненную область экрана.
- **Шапка (`Navbar.tsx`):**
  - Кнопка-гамбургер (`Menu`) видна только на экранах `< lg`.
  - Второстепенные статусные бейджи («Online», «FastAPI») плавно скрываются на смартфонах, предотвращая вытеснение управляющих элементов.
  - **Адаптивный переключатель периода:** На мобильных экранах (`< sm`) заменяется на нативный выпадающий список `<select>`, а на десктопах (`sm:flex`) отображаются классические сегментированные кнопки-пилюли.
  - Кнопки действий (`+ Операция`, `Сброс демо`) адаптируются: на мобильных показываются компактные иконки, на планшетах и десктопах — полные текстовые подписи.

### 5.3. Горизонтальная прокрутка таблиц (Touch Tables)
Таблицы со множеством колонок (Дашборд, Финансы, Закупки, Прогноз остатков, История импорта) на узких экранах не сжимают текст до нечитаемого состояния:
- Обернуты в контейнеры с плавным горизонтальным скроллом `overflow-x-auto`.
- На мобильных контейнер вытягивается в край экрана (`-mx-4 sm:mx-0`) с сохранением внутренних отступов.
- Заданы фиксированные минимальные ширины (`min-w-[560px]`–`min-w-[780px]`), гарантирующие читаемость валюты (₸ KZT), дат, поставщиков и числовых расчетов.

### 5.4. Графики и экспресс-калькулятор партии
- **Диаграммы (`Recharts`):** Высота контейнеров адаптирована (`h-44 sm:h-52` в модальных окнах, `h-56 sm:h-64` на дашборде), предотвращая наползание осей координат и подписей дат.
- **Интерактивный калькулятор:** На экранах `< lg` калькулятор перестраивается в вертикальный блок с полноразмерным слайдером для удобного перетаскивания пальцем.

### 5.5. Безопасность модальных окон при экранной клавиатуре
- В `AddTransactionModal.tsx` и `ProductHistoryModal.tsx` заданы свойства `max-h-[92dvh] overflow-y-auto` и `p-3 sm:p-4`.
- При вызове виртуальной клавиатуры на смартфоне поля ввода не уходят за пределы видимости, а прокручиваются внутри окна.
- В модальном окне истории цен карточки текущей и прошлой цены перестраиваются из трёх колонок в одну (`grid-cols-1 sm:grid-cols-3`).

## 6. Запуск и сборка

### Локальный запуск в режиме разработки:
```bash
cd frontend
npm install
npm run dev
```
Сервер разработки запустится по адресу: `http://localhost:5173`.

### Сборка продакшен-бандла:
```bash
npm run build
```
Статические файлы генерируются в папку `dist/`.

### Проверка типов:
```bash
npx tsc -b
```
