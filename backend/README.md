## 1. Назначение и архитектурные принципы

Бэкенд BizMind предоставляет высокопроизводительный, строго типизированный REST API для оперативного управления закупками, складскими остатками, финансовыми потоками и аналитической отчетностью предприятий малого бизнеса (HoReCa и ритейл).

### Ключевые архитектурные принципы:
1. **Детерминированная аналитика без непрозрачного AI:** все расчеты скачков цен, подтвержденной экономии, среднесуточного потребления сырья и прогноза истощения остатков производятся прозрачными алгоритмами.
2. **Строгая мультитенантность (Row-Level Isolation):** данные изолируются на уровне каждой строки через обязательный внешний ключ `organization_id`.
3. **Глобальный общий каталог поставщиков:** поставщики маркетплейса имеют `is_global = True` и `organization_id = NULL`, защищены от модификации арендатором и доступны всем организациям.
4. **Блокировка цен по каталогу (Catalog Price Locking):** оформление заказов осуществляется строго по актуальным предложениям поставщика с проверкой квантов закупки (MOQ) и минимальной суммы (MOA).
5. **Складской партионный аудит:** любые изменения остатков фиксируются в таблице `inventory_movements` с указанием документа-основания и автора.
6. **Автоматическая синхронизация закупок и финансов:** оприходование заказа на склад автоматически формирует складской приход (`receipt`) и расходную транзакцию (`expense`) с маркировкой `purchase_order_id`, исключая двойной учет.

## 3. База данных и модели (15 сущностей)

Подробное описание схемы, типов полей, связей, ER-диаграммы и правил целостности вынесено в отдельный документ:  
👉 **[Документация базы данных (DATABASE.md)](DATABASE.md)**.

### Перечень таблиц:
1. `organizations` — профили предприятий и пороги алертов
2. `users` — сотрудники, роли (`owner`, `manager`, `employee`), хеши паролей
3. `products` — номенклатура сырья и упаковки (SKU, единица, страховой запас)
4. `suppliers` — поставщики (условия доставки, минимальный заказ, статус `is_global`)
5. `supplier_offers` — прайс-листы поставщиков (цены, MOQ, кратность упаковки)
6. `offer_price_history` — аудит изменения цен поставщиков
7. `purchase_orders` — документы заказов (`draft`, `confirmed`, `received`, `cancelled`)
8. `purchase_order_items` — позиции заказа со зафиксированными ценами каталога
9. `inventory_movements` — журнал складских движений (`receipt`, `write_off`, `adjustment`)
10. `purchases` — денормализованный архив фактических закупок
11. `financial_transactions` — ДДС (доходы и расходы по категориям)
12. `notifications` — алерты инфляции цен, нехватки остатков и рекомендаций
13. `import_batches` — реестр загрузок внешних файлов Excel/CSV
14. `activity_logs` — аудит действий пользователей системы
15. `report_templates` — сохраненные шаблоны конструктора отчетов

## 4. Безопасность и аутентификация

* **Криптография:** Хеширование паролей выполняется с использованием алгоритма **PBKDF2-HMAC-SHA256** со 100 000 итераций и криптографической солью (`backend/src/backend/security.py`). Открытые пароли никогда не сохраняются в базе.
* **Генератор паролей:** Предоставляет генерацию 12-значных криптостойких случайных паролей, включающих заглавные/строчные буквы, цифры и спецсимволы.
* **Ролевой доступ (RBAC):**
  * `owner` — полный доступ к управлению организацией, бюджетами и сотрудниками.
  * `manager` — управление закупками, складом и поставщиками.
  * `employee` — просмотр остатков и фиксация складских операций.

## 5. Алгоритмы бизнес-аналитики

### 5.1. Детекция скачков цен
$$\Delta P = \frac{P_{new} - P_{old}}{P_{old}} \times 100\%$$
Если $\Delta P \ge \text{threshold}$ (по умолчанию 5%), позиция помечается как риск и генерируется уведомление `price_spike`.

### 5.2. Сравнение предложений и учет логистики
$$\text{Cost} = Q \times P_{unit} + \text{DeliveryCost}$$
Система сопоставляет полную стоимость партии с учетом порога минимального заказа поставщика (MOA) и минимального кванта позиции (MOQ).

### 5.3. Прогноз расхода и исчерпания склада
$$\text{DailyBurnRate} = \frac{\sum Q_{consumption}}{\text{DaysWindow}}$$
$$\text{DaysRemaining} = \frac{\text{CurrentStock}}{\text{DailyBurnRate}}$$
Если данных о расходе недостаточно, система честно возвращает статус `insufficient_data` без генерации ложных цифр.

## 6. Автоматические миграции и сидирование

* При старте приложения вызывается `run_auto_migrations()` (`backend/src/backend/migrations.py`). Функция инспектирует таблицы SQLite, создает недостающие таблицы, добавляет новые колонки через `ALTER TABLE ADD COLUMN` и бэкфиллит дефолтные значения.
* База данных поддерживает детерминированное сидирование:
  * Через API: `POST /api/demo/reset`
  * Через CLI: `uv run python -m backend.demo.seed_data`

## 7. API Спецификация (Ключевые эндпоинты)

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/health` | Проверка жизнеспособности сервиса |
| `POST` | `/api/auth/login` | Вход пользователя по email и паролю |
| `GET` | `/api/dashboard/stats` | Сводные KPI метрики бизнеса |
| `GET` | `/api/suppliers/{id}/catalog` | ⭐ **Каталог товаров выбранного поставщика с ценами и MOQ** |
| `GET` | `/api/suppliers/compare` | Матрица сравнения предложений контрагентов |
| `GET` | `/api/orders` | Список сформированных заказов |
| `POST` | `/api/orders` | Создание заказа с валидацией по каталогу поставщика |
| `PUT` | `/api/orders/{id}` | ⭐ **Редактирование позиций черновика заказа** |
| `POST` | `/api/orders/{id}/receive` | ⭐ **Оприходование поставки на склад (склад + расход)** |
| `GET` | `/api/inventory` | Текущие остатки номенклатуры |
| `POST` | `/api/inventory/write-off` | Списание сырья (брак, порча) |
| `POST` | `/api/inventory/adjust` | Инвентаризация остатков |
| `GET` | `/api/inventory/export` | Выгрузка ведомости остатков в Excel (`.xlsx`) |
| `POST` | `/api/reports/generate` | Генерация данных кастомного отчета |
| `POST` | `/api/reports/export` | Экспорт отчета в Excel (`.xlsx`) или CSV |
| `POST` | `/api/settings/employees` | Регистрация сотрудника с генерацией пароля |

Полный список маршрутов доступен в документе [`docs/API.md`](../docs/API.md) и через Swagger UI (`/docs`).
