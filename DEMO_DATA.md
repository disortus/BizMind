# Демонстрационные сценарии и каталог поставщиков BizMind

## 1. Концепция двух демонстрационных сценариев

В BizMind реализованы две демонстрационные организации с принципиально разным жизненным циклом и начальным состоянием:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        ОРГАНИЗАЦИИ В BIZMIND                           │
├───────────────────────────────────┬────────────────────────────────────┤
│     Сценарий A: «Cafe Aroma»      │      Сценарий B: «Daily Cup»       │
│    (Только что внедрили систему)  │    (6 месяцев зрелой эксплуатации) │
├───────────────────────────────────┼────────────────────────────────────┤
│ • 0 финансовых операций           │ • 76 финансовых операций           │
│ • 0 закупленных партий            │ • 28 закупок за 6 месяцев          │
│ • 0 складских остатков            │ • 10 товаров на складе             │
│ • 0 ложных алертов и прогнозов    │ • 153 200 ₸ подтвержденной         │
│ • Экран пошагового внедрения      │   реализованной экономии           │
│ • Файлы для ручного онбординга    │ • История цен и динамика затрат    │
│ • Доступен каталог поставщиков    │ • Управленческие отчеты            │
└───────────────────────────────────┴────────────────────────────────────┘
```

## 2. Сценарий A: Cafe Aroma — первоначальное внедрение

### 2.1. Описание кофейни
«Cafe Aroma» — реально существующая кофейня, которая вела учёт в таблицах Excel и накопила исторические данные до внедрения BizMind. Однако на момент первого входа в систему её данные **ещё не были импортированы**.

### 2.2. Поведение пустой организации при первом входе
- **Финансы:** 0 операций, доходы и расходы равны 0 ₸, маржинальность не отображается фиктивными процентами.
- **Закупки:** 0 записей, отсутствуют ложные всплески закупочных цен.
- **Склад:** 0 товаров, складской баланс 0 ₸.
- **Прогнозирование:** возвращает честный статус `insufficient_data` («Недостаточно данных для построения расхода и прогноза запасов»).
- **Центр уведомлений:** не спамит ложными предупреждениями о дефиците или просрочке.
- **Дашборд:** активирует специализированный режим **онбординга (Onboarding Roadmap)**:
  - Приветствие владельца и статус («Исторические данные ещё не импортированы»).
  - Карточки 4 последовательных шагов внедрения со ссылками на образцы файлов.
  - Кнопки быстрого перехода в модуль импорта.

### 2.3. Демонстрационные файлы для постепенного импорта
Файлы для онбординга подготовлены в каталоге `demo_data/onboarding/cafe_aroma/`:

1. **`historical_finances.xlsx`** (53 операции)
   - Операционные доходы от кассы и расходы на аренду, коммуналку, зарплату, сырьё за июнь — август 2026 г.
2. **`historical_purchases.xlsx`** (31 партия)
   - Реальные партии поставок кофейного зерна, молока, сиропов, бумажных стаканов.
3. **`historical_inventory.xlsx`** (10 складских SKU)
   - Начальные остатки на складе: кофе, молоко, сиропы, стаканы, сахар, салфетки.
4. **`supplier_price_lists.xlsx`** (10 позиций прайс-листов)
   - Предложения поставщиков с ценами и условиями минимального заказа.

### 2.4. Постепенное раскрытие функционала
1. **Вход в Cafe Aroma** -> Дашборд онбординга, нулевые финансовые и складские показатели.
2. **Импорт `historical_finances.xlsx`** -> Заполняется раздел финансов, строится структура затрат и график операционной прибыли.
3. **Импорт `supplier_price_lists.xlsx`** -> Появляются предложения в разделе сравнения цен, история цен и бенчмаркинг.
4. **Импорт `historical_inventory.xlsx`** -> Заполняется раздел склада, появляется оценка себестоимости хранения.
5. **Импорт `historical_purchases.xlsx`** -> Рассчитывается среднесуточный расход сырья, модуль прогнозирования строит дни до исчерпания остатков, уведомления начинают сигнализировать о реальных изменениях.

## 3. Сценарий B: Daily Cup — длительная зрелая эксплуатация

### 3.1. Описание кофейни
«Daily Cup» — кофейня, использующая BizMind на протяжении **6 месяцев (май — октябрь 2026 г.)**. Накопленная история демонстрирует, как принятие решений на основе аналитики позволяет оптимизировать затраты и повысить устойчивость бизнеса.

### 3.2. Математическое обоснование реализованной экономии
В отличие от абстрактных обещаний, в Daily Cup зафиксирована **фактическая реализованная экономия 153 200 ₸**, подтвержденная историей заказов:

1. **Бумажные стаканы 300 мл (Одноразовая упаковка)**
   - Базовая цена старого поставщика: **28 ₸ / шт.**
   - Альтернативное предложение «ЭкоТорг»: **19 ₸ / шт.** (-9 ₸ / шт.).
   - Фактически закуплено за июль — сентябрь: **3 800 шт.** (2 партии по 1 900 шт.).
   - Реализованная экономия: `3 800 * 9 = 34 200 ₸`.

2. **Кофе в зернах Espresso Blend 100% Arabica**
   - Базовая цена (розничная): **7 800 ₸ / кг.**
   - Согласованная оптовая цена от «Silk Road Coffee Co.» при партии от 20 кг: **6 400 ₸ / кг.** (-1 400 ₸ / кг.).
   - Фактически закуплено за июнь — сентябрь: **60 кг.** (3 партии по 20 кг).
   - Реализованная экономия: `60 * 1 400 = 84 000 ₸`.

3. **Молоко ультрапастеризованное 3.2%**
   - Базовая цена прежнего поставщика: **520 ₸ / л.**
   - Прямой контракт с «Parmalat Professional»: **450 ₸ / л.** (-70 ₸ / л.).
   - Фактически закуплено за август — сентябрь: **500 л.** (2 партии по 250 л.).
   - Реализованная экономия: `500 * 70 = 35 000 ₸`.

**ИТОГО ПОДТВЕРЖДЕННАЯ РЕАЛИЗОВАННАЯ ЭКОНОМИЯ:**  
`34 200 + 84 000 + 35 000 = 153 200 ₸`.

### 3.3. Различие потенциальной и реализованной экономии
- **Потенциальная экономия:** рассчитывается в модуле сравнения цен на основе еще не заказанных коммерческих предложений из каталога для гипотетического объема партии.
- **Реализованная экономия:** рассчитывается строго на основе фактически оформленных и принятых заказов (`purchases`), сопоставленных с прежней базовой ценой закупки тех же SKU.

### 4.2. Правила мультитенантности и происхождения
- **Источник поставщика (`source_type`):**
  - `global` («Из базы BizMind») — общий поставщик каталога, `organization_id = None`, `is_global = True`.
  - `imported` («Импортирован») — создан организацией через импорт Excel-прайс-листа.
  - `manual` («Вручную») — создан пользователем через экран добавления.
- **Источник прайс-листа (`price_source`):**
  - `global_catalog` («Прайс: Из каталога BizMind»)
  - `imported` («Прайс: Загружен пользователем»)
  - `manual` («Прайс: Ручной ввод»)
- **Защита целостности:** Запросы на редактирование (`PUT`) или удаление (`DELETE`) глобальных поставщиков от арендатора отклоняются с кодом `HTTP 403 Forbidden`. Пользовательский импорт дублирующего поставщика не изменяет глобальную запись.

## 5. Воспроизводимость данных (Seed Scripts)

Для повторной инициализации демонстрационной базы данных используется команда:
```bash
python -m backend.demo.seed_data
```
Команда идемпотентна, очищает и перезаполняет базу строго по заданным правилам:
- Создает 4 системных шаблона отчетов.
- Создает 5 глобальных поставщиков и их предложения.
- Создает организацию «Cafe Aroma» с 0 финансовыми и складскими записями.
- Создает организацию «Daily Cup» с 6 месяцами согласованной операционной истории.
