## 2. Команды для запуска тестов

### 2.1. Запуск бэкенд-тестов (Pytest)
```bash
cd backend
uv run pytest -v
```

Для запуска конкретного модуля:
```bash
uv run pytest tests/test_educational_mvp.py -v
```

Для запуска с выводом покрытия (coverage):
```bash
uv run pytest --cov=backend tests/
```

### Модуль 2: `test_educational_mvp.py` (Новая функциональность MVP)
1. `test_rbac_and_user_creation`:
   - Проверяет ролевую модель: только пользователь с ролью `Owner` может регистрировать новых сотрудников.
   - Проверяет криптографическое хеширование паролей (PBKDF2-HMAC-SHA256, отсутствие паролей в открытом виде).
   - Проверяет запрет создания пользователей для сотрудника с ролью `Employee` (HTTP 403 Forbidden).
   - **Результат: PASSED**.
2. `test_product_catalog_crud`:
   - Проверяет создание товара с артикулом (SKU), категорией и единицей измерения.
   - Проверяет поиск по каталогу, обновление реквизитов и архивацию/удаление.
   - **Результат: PASSED**.
3. `test_supplier_and_price_history_crud`:
   - Проверяет создание поставщика с условиями доставки и минимальным заказом.
   - Проверяет регистрацию коммерческих предложений (`SupplierOffer`) и фиксацию истории изменений цен в таблице `offer_price_history`.
   - **Результат: PASSED**.
4. `test_purchase_order_lifecycle_and_inventory_reception`:

## 5. Известные ограничения и непроверенные сценарии

1. **Внешние API поставщиков:**
   - В текущем MVP интеграция с реальными внешними API (1С, МойСклад, EDI) не реализуется нарочно в соответствии с ТЗ. Обмен прайсами осуществляется через Excel/CSV и ручной ввод.
2. **Анализ списаний с рецептурными картами (технологические карты):**
   - Автоматическое списание граммов кофе на каждую проданную чашку эспрессо (кассовая интеграция с фискальным регистратором) в учебном MVP моделируется через периодические инвентаризации и ручные складские движения.
3. **Хранилище SQLite в многопользовательском режиме:**
   - SQLite идеально подходит для локальной демонстрации и учебного MVP одного заведения. Для масштабирования на сотни одновременных распределенных пользователей рекомендуется переход на PostgreSQL.
