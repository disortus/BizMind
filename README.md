# BizMind — полное описание продукта

BizMind — это планируемая цифровая платформа для малого бизнеса, которая объединяет финансовую аналитику и управление закупками в одном интерфейсе. Её задача — помогать предпринимателю понимать, на что уходят деньги компании, как меняются расходы, у каких поставщиков выгоднее закупаться и какие товары следует заказывать в дальнейшем.

Платформа ориентирована прежде всего на небольшие кафе, рестораны и магазины, а в перспективе — на сервисные компании и небольшие производства. Для таких предприятий BizMind должен стать инструментом оперативного управления финансами и закупками, не требующим найма отдельного финансового аналитика или специалиста по закупкам.

На данный момент BizMind — бизнес-концепция, а не готовое программное обеспечение. Описанные функции являются планируемыми; их полезность и готовность клиентов платить за сервис предстоит проверить на пилотном запуске.

BizMind состоит из нескольких взаимосвязанных функциональных частей:

- Финансовая аналитика — анализ операций и расходов предприятия.
- Аналитика закупок — история покупок, поставщики, цены и условия предложений.
- Сравнение поставщиков — сопоставление стоимости одинаковых или сопоставимых товаров.
- Прогнозирование закупок — оценка будущей потребности в товарах на основе истории покупок и доступных данных.
- Уведомления и рекомендации — сообщения о существенных изменениях цен, необычных расходах и необходимости пополнить запасы.

Ключевой принцип BizMind — не просто отображать данные, а связывать финансовую информацию с закупочной деятельностью, чтобы предприниматель мог принимать более обоснованные решения.

## 2. Для кого предназначен BizMind

Основные пользователи — владельцы и управляющие малым бизнесом.

- Кафе и рестораны: анализ закупок продуктов, кофе, напитков, упаковки и расходных материалов.
- Магазины: контроль стоимости закупаемых товаров, сравнение поставщиков и планирование пополнения запасов.
- Сервисные компании: анализ расходов на материалы, оборудование и расходники.
- Небольшие производства: в перспективе — анализ стоимости сырья и планирование его закупок.

Начинать рациональнее с кафе и небольших магазинов: у них регулярно повторяются закупки, есть история расходов, а цены на многие товары можно сопоставлять между поставщиками.

## 4. Пример использования: кафе закупает кофе

Предположим, небольшое кафе регулярно покупает кофе у одного поставщика.

Условный сценарий работы BizMind — не реальные результаты тестирования

Прежняя цена

# 10 000 ₸

За условную единицу закупки

Новая цена

# 11 500 ₸

Рост на 15%

BizMind фиксирует изменение цены в доступных данных и показывает, что другой поставщик предлагает сопоставимый товар за 10 350 ₸.

Потенциальная разница

# 1 150 ₸

На одной условной единице закупки по сравнению с новой ценой прежнего поставщика.

Прежде чем считать разницу экономией, предпринимателю нужно проверить сопоставимость товара, доставку, минимальный заказ и остальные условия. Фактическая выгода пока не подтверждена.

В этом сценарии BizMind не покупает товар автоматически и не принимает решение вместо предпринимателя. Платформа предоставляет информацию для выбора: остаться у прежнего поставщика, договориться о цене или рассмотреть альтернативу.

## 5. Что именно будет входить в первую версию — MVP

Первая версия должна подтвердить основную ценность продукта без затрат на создание сложной системы интеграций.

| Модуль                | Что планируется реализовать                          |
| --------------------- | ---------------------------------------------------- |
| Загрузка данных       | Импорт CSV и Excel                                   |
| Финансы               | Категоризация операций, графики и динамика расходов  |
| Закупки               | История покупок и каталог поставщиков                |
| Сравнение цен         | Сопоставление товаров и доступных предложений        |
| Правила и уведомления | Настраиваемые пороги изменения цен и расходов        |
| Планирование          | Базовый статистический прогноз потребности в товарах |
| Интерфейс             | Веб-панель с общим обзором финансов и закупок        |

В MVP не обязательно сразу подключать все банки, кассовые системы и магазины поставщиков. На старте можно работать с загруженными файлами и ограниченным набором данных, которые удастся получить и привести к сопоставимому виду.

### Что появится позже

- Интеграции с банковскими, кассовыми и учётными системами через доступные API.
- Автоматическое обновление данных о ценах из поддерживаемых источников.
- Более гибкое прогнозирование с учётом сезонности и изменений спроса.
- Расширенные отчёты и настройки для разных типов бизнеса.
- Возможность оформлять закупки через партнёров и получать комиссию от сделок, если такая модель будет подтверждена.

Это этапы развития, а не функции, которые уже существуют.

## 6. Техническая реализация

Для первой версии рационально выбрать архитектуру, которую небольшая команда сможет реализовать и поддерживать самостоятельно.

Веб-интерфейс BizMind

Панель расходов, закупок, поставщиков и уведомлений

Backend и API

Авторизация, обработка данных, бизнес-правила и аналитика

База данных

Пользователи, компании, операции, товары и цены

Источники данных

Импорт файлов и подключаемые внешние сервисы

Упрощённая планируемая архитектура MVP

Основные технические принципы:

- Монолитный backend на первом этапе. Аналитика, закупки, импорт и правила работают в одном приложении, разделённом на логические модули.
- Единая база данных с разделением по организациям. Каждая компания видит только собственные данные; модель должна учитывать пользователей, организации и при необходимости отдельные филиалы.
- API для обмена данными. Интерфейс взаимодействует с backend, а внешние системы подключаются по мере необходимости.
- Автоматизация по расписанию. Импорт, обновление доступных данных и расчёты можно запускать периодически.
- Защита данных. Предусматриваются авторизация, разграничение доступа, проверка входных файлов, резервное копирование и безопасное хранение учётных данных интеграций.

В качестве технических решений можно рассматривать Python для backend, PostgreSQL для хранения данных и веб-технологии для интерфейса. Окончательный стек зависит от ресурсов команды и требований MVP.

Важно: BizMind не должен подменять бухгалтерскую систему. Он использует финансовые данные для управленческой аналитики, а не для полноценного ведения бухгалтерского и налогового учёта. Искусственный интеллект в концепцию не входит: расчёты предполагается выполнять с помощью правил, статистики и алгоритмов обработки данных.

## 7. Как BizMind будет зарабатывать

Основная модель монетизации — SaaS-подписка, то есть регулярная плата за использование платформы.

1\. Подписка для бизнеса — основной источник дохода

Клиенты платят за доступ к расширенной аналитике, сравнению закупок, уведомлениям, прогнозированию и отчётам. Тарифы можно различать по числу пользователей, филиалов, объёму данных и доступным функциям. Цену необходимо определить после исследования клиентов и пилота.

2\. Комиссия с закупок — потенциальный дополнительный доход

На более позднем этапе BizMind сможет направлять клиентов к поставщикам или поддерживать оформление заказов через партнёров. Если сделка состоится, платформа сможет получать согласованную комиссию. Для этого потребуются партнёрства и подтверждение того, что такой формат интересен обеим сторонам.

3\. Расширенные тарифы — перспектива развития

В дальнейшем можно предложить дополнительные возможности для сетей с несколькими филиалами, расширенные отчёты, интеграции и централизованную аналитику.

На старте модель должна опираться прежде всего на подписку. Доходы от комиссий и расширенных тарифов нельзя считать гарантированными, пока не появятся реальные клиенты и партнёры.

## 9. Как проверить, что BizMind действительно нужен рынку

До масштабной разработки необходимо подтвердить, что предпринимателям нужен именно такой продукт и что они готовы за него платить.

Предлагаемый план проверки:

1. Провести 10–15 интервью с владельцами и управляющими кафе и магазинов. Узнать, как они сейчас анализируют расходы, сравнивают поставщиков и планируют закупки.
2. Собрать прототип и MVP с импортом файлов, финансовой аналитикой и ограниченным модулем сравнения закупок.
3. Запустить пилот у 3–5 предприятий, если удастся договориться с участниками.
4. Измерить результаты: сколько времени занимает анализ, какие изменения цен удаётся обнаружить, как часто используются функции и готовы ли клиенты продолжить работу на платной основе.
5. Скорректировать продукт и тарифы на основе обратной связи и реальных результатов.

Эти числа — целевые ориентиры плана проверки, а не уже проведённые исследования.

## 10. Чем BizMind отличается от альтернатив

BizMind не стремится заменить все существующие бухгалтерские, складские и ERP-системы. Его предполагаемая специализация — связать анализ расходов с анализом закупок в одном инструменте.

- В отличие от обычной таблицы, платформа должна автоматически обрабатывать данные, показывать динамику и отслеживать заданные условия.
- В отличие от системы бухгалтерского учёта, BizMind ориентируется на управленческие решения и закупочную аналитику.
- В отличие от отдельного каталога поставщиков, платформа должна учитывать историю закупок самого предприятия и сопоставлять её с доступными предложениями.

При этом подобные функции по отдельности уже могут существовать у других сервисов. Поэтому преимущество BizMind необходимо подтвердить сравнением с конкурентами и пилотным использованием, а не заявлять как доказанный факт.

## Итоговое позиционирование

BizMind — это планируемая SaaS-платформа управленческой аналитики для малого бизнеса. Она объединяет обработку финансовых данных, анализ закупок, сравнение предложений поставщиков, базовое прогнозирование потребности в товарах и уведомления на основе правил. Продукт будет развиваться от простого MVP с загрузкой файлов к интеграциям с внешними системами и более автоматизированному управлению закупками.

Главная ценность BizMind — помочь предпринимателю принимать решения о расходах и закупках на основании собранных и проанализированных данных, а не только вручную просматривать таблицы и счета. Успех проекта будет зависеть от качества исходных данных, удобства использования, точности сравнений, реальной пользы для бизнеса и готовности клиентов платить за сервис.

# Руководство по запуску и демонстрации MVP BizMind (Cafe Aroma & Daily Cup)

В проекте реализованы **два независимых демонстрационных пространства** с полной изоляцией данных:
1. **Кейс A: Cafe Aroma** — *«Первоначальное внедрение»*. Кофейня только переходит с Excel-учёта в BizMind. Загружены стартовые данные, доступен живой импорт Excel, обнаружен рост цен на кофе (+15%).
2. **Кейс B: Daily Cup** — *«Регулярное использование»*. Кофейня использует BizMind 5+ месяцев. Обширная история закупок, стабильная финансовая аналитика, скачок цен на одноразовую посуду (крафтовые стаканы 250 мл на +18.3%).

---

## 1. Быстрый запуск

### Способ 1: Через Docker Compose (Рекомендуемый для Production & Staging)
Все сервисы (Nginx + production-сборка React 19 frontend, FastAPI backend на Python 3.12, постоянный SQLite-том) поднимаются одной командой:
```bash
# Проверка синтаксиса конфигурации
docker compose config

# Сборка образов и запуск в фоновом режиме
docker compose up -d --build

# Проверка статуса
docker compose ps
```
После старта приложение доступно по единому адресу: **http://localhost** (или порту `80`).  
API автоматически проксируется через Nginx по относительному пути `/api/`.

Остановка контейнеров (данные в томе сохраняются):
```bash
docker compose down
```

---

### Способ 2: Локальный запуск для разработки

#### Требования
- Python 3.12+ и установленный менеджер пакетов [uv](https://docs.astral.sh/uv/)
- Node.js 18+ и npm

#### 1.1. Запуск Backend
```bash
cd backend
# Установка зависимостей и запуск сервера FastAPI на порту 8000
uv run uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload
```
API будет доступно по адресу: [http://localhost:8000](http://localhost:8000)  
Интерактивная документация Swagger: [http://localhost:8000/docs](http://localhost:8000/docs)

*Примечание: При старте backend инициализирует SQLite-базу `bizmind.db` и детерминированно заполняет данные для обеих организаций, а также генерирует демонстрационные Excel-файлы в `demo_data/`.*

#### 1.2. Запуск Frontend
В отдельном окне терминала:
```bash
cd frontend
npm install
npm run dev
```
Интерфейс откроется по адресу: [http://localhost:5173](http://localhost:5173)

## 2. Автоматическое тестирование изоляции данных

В проекте разработан автоматизированный тестовый набор Pytest, проверяющий строгую изоляцию данных между организациями (финансы, закупки, товары, остатки, прогноз, импорт, дашборд):
```bash
cd backend
uv run pytest tests/test_isolation_and_demo.py -v
```
Все 7 интеграционных тестов выполняются в чистой транзакционной сессии и гарантируют, что данные Cafe Aroma и Daily Cup никогда не смешиваются.

### Краткий обзор двух пространств:

| Параметр | Кейс A: Cafe Aroma | Кейс B: Daily Cup |
|---|---|---|
| **Сценарий** | Первоначальное внедрение (миграция с Excel) | Регулярное использование (5+ месяцев в системе) |
| **Управляющий** | Алексей Смирнов | Данияр Касымов |
| **Ключевой инцидент** | Рост цены на зерновой кофе на **+15.0%** (с 10 000 до 11 500 ₸/кг) | Рост цены на крафтовые стаканы 250 мл на **+18.3%** (с 1 200 до 1 420 ₸/уп) |
| **Текущий поставщик** | Coffee Roasters Hub | PackGroup Almaty |
| **Лучшая альтернатива** | Aroma Direct (10 350 ₸/кг, разница 1 150 ₸/кг) | EcoTorg Kazakhstan (1 230 ₸/уп, разница 190 ₸/уп) |
| **Потенциал партии** | 23 000 ₸ (на партию 20 кг) | 9 500 ₸ (на партию 50 упаковок) |
| **Критический остаток** | Молоко 3.2% (12 л при норме 25 л) | Капхолдеры 2-местные (6 уп при норме 12 уп) |
| **Импорт** | Доступны файлы в `demo_data/` для живого показа | Используется для периодической выгрузки реестров |
